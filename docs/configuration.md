# Configuration reference

A cluster directory (default `./clusters/<name>/`, or `--dir`) contains:

| File | Purpose |
|---|---|
| `install-config.yaml` | standard OKD install config (validated, never modified) |
| `cluster.yaml` | Proxmox settings and node topology (this page) |
| `proxmox.conf` | credentials, mode 600 |
| `preboot/` | your own Pre-Boot manifests (`.bu`, `.yaml`) |
| `pull-secret.json`, `mirror-auth.json`, `proxmox-csi.conf`, `ceph-csi.conf` | optional secrets, mode 600 |

Generated by `okd-pve`, all ignored by the `.gitignore` that `init` writes:
`.generated/` (installer directory), `.state/` (progress, node inventory),
`tofu/` (OpenTofu root module and state), `auth/` (kubeconfig,
kubeadmin password), `bin/` (downloaded tools), `logs/`.

## install-config.yaml

The standard format, without an own DSL on top. Requirements:

- `platform.baremetal.apiVIPs` and `ingressVIPs` (lists). The cluster brings
  its own VIPs via keepalived; no external load balancer, no BMC data, no
  `hosts` (they are generated into `agent-config.yaml`).
- Single node: `platform: {none: {}}`; DNS for `api`, `api-int` and
  `*.apps` points to the node.
- `networking.machineNetwork` must contain all node IPs.

Filled in by `okd-pve` (in the generated copy only):
`controlPlane.replicas` and `compute[0].replicas` from the node groups
(when set in the file, they must match), `pullSecret` and `sshKey` when
missing. With `registry_mirrors`, also `imageDigestSources`, the mirror
hosts in `proxy.noProxy` and the mirror credentials in `pullSecret`.

## proxmox.conf

| Key | Example | Notes |
|---|---|---|
| `PROXMOX_VE_ENDPOINT` | `https://pve.example.com:8006/` | any cluster node |
| `PROXMOX_VE_API_TOKEN` | `terraform-okd@pve!okd=<uuid>` | `user@realm!tokenid=secret` |
| `PROXMOX_VE_INSECURE` | `false` | `true` accepts self-signed certificates |

Sourced as shell. Environment variables with the same names override the
file. The file is refused if group or others can read it. Override the path
with `OKD_PVE_PROXMOX_CONF`.

## cluster.yaml

Unset keys take the defaults from
[templates/cluster-defaults.yaml](../templates/cluster-defaults.yaml).
Maps are merged key by key; lists replace the default list.

### okd

| Key | Default | Description |
|---|---|---|
| `okd.version` | – (required) | OKD release tag, e.g. `4.21.0-okd-scos.11`; ≥ 4.17. Determines `openshift-install`/`oc` downloads and, through the release payload, the SCOS version. |

### install

| Key | Default | Description |
|---|---|---|
| `install.pull_secret_file` | `""` | pull secret if `install-config.yaml` has none. Order: install-config → `$OKD_PVE_PULL_SECRET_FILE` → this → `<cluster>/pull-secret.json` → OKD placeholder |
| `install.additional_ssh_keys` | `[]` | more public keys for the `core` user. Only the first key of `sshKey`/key file goes into the generated install-config (more break Metal3/Ironic on baremetal); all others, including extra lines of `sshKey`, become the Pre-Boot MachineConfigs `99-{master,worker}-okd-pve-ssh` |
| `install.iso_max_age_hours` | `20` | the agent ISO contains certificates valid for 24 h; while no VM has booted it, `create` rebuilds an older ISO |
| `install.recover_stuck_hosts` | `true` | while `create` waits for the installation: if the agent installer gave up on a host after its disk was written (fixed stage timeouts, typically slow image downloads) and it stays in the live ISO, reset its VM once so it boots from its installed disk, and approve its CSRs. The trigger is the host state the in-cluster `assisted-installer-controller` logs while the node is missing from `oc get nodes`: `error` in "Waiting for control plane" for a worker, in "Waiting for controller" for the rendezvous node. The 0.1.2 name `install.recover_rendezvous: false` also turns it off. See the README, Troubleshooting |
| `install.debug_shell` | `false` | debugging only: the agent ISO (and the ISOs of `node add`) get the kernel argument `systemd.debug_shell`, so every node has a **root shell without password on tty9** while it runs from the ISO. Use it when an installation hangs on a node you cannot reach by SSH, for example bootkube on the rendezvous node. Proxmox console: Ctrl+Alt+F9 (noVNC side panel: toggle Ctrl and Alt, then press F9), or `qm sendkey <vmid> ctrl-alt-f9` on the host. Installed nodes are not affected. Takes effect when the ISO is built, so set it before `create` (after `destroy` for a running installation) |
| `install.ssh_public_key_file` | `""` | SSH key if install-config has none. Order: install-config → `$OKD_PVE_SSH_PUBLIC_KEY_FILE` → this → `~/.ssh/id_ed25519.pub`, `id_ecdsa.pub`, `id_rsa.pub` |

### proxmox

| Key | Default | Description |
|---|---|---|
| `nodes` | – | Proxmox nodes for the VMs |
| `spread` | `true` | `true`: round-robin by node index over the nodes, in every group from the first node (control plane on different hosts). `balanced`: like `true`, but every group starts one node further (group position in `node_groups`), so the VMs spread evenly over the hosts: with 2 hosts and 3 groups of 3, 5:4 instead of 6:3. `false`: all on the first. Set it before `create`; changing it later would move existing VMs, which `okd-pve` refuses |
| `vm_storage` | `local-lvm` | boot disks (content `images`) |
| `iso_storage` | `local` | agent/node ISOs (content `iso`); uploaded once if `shared`, else to every host used |
| `efi_storage` | `""` | EFI vars disks; default `vm_storage` |
| `bridge` | `vmbr0` | bridge or SDN VNet |
| `vlan_tag` | `0` | VLAN tag on the NIC, `0` = untagged |
| `pool` | `okd-<cluster>` | existing resource pool for all VMs |
| `vmid_start`, `vmid_end` | – | VMID range |
| `vmid_block` | `20` | VMIDs reserved per node group (offset = position × block) |
| `mac_prefix` | `02:00:00` | 2–4 bytes; MAC = prefix + VMID |
| `cpu_type` | `host` | QEMU CPU model; SCOS 10 needs `x86-64-v3` or `host`. With HA or live migration between hosts with different CPUs use a named model such as `x86-64-v3`. |
| `bios` | `ovmf` | `ovmf` (UEFI, no pre-enrolled keys) or `seabios` |
| `machine` | `q35` | QEMU machine type |
| `tmp_dir` | `""` | local temporary directory, used as `TMPDIR` by okd-pve and every tool it starts: the ~1 GiB ISO upload buffer (also passed to the provider as `tmp_dir`), tool downloads, openshift-install. Needs ~2 GiB. Relative paths are relative to the cluster directory, e.g. `.tmp`. Default `$TMPDIR` or `/tmp` |
| `cache_dir` | `""` | local cache directory, used as `XDG_CACHE_HOME`: openshift-install keeps the ~1 GiB base ISO there (`agent/image_cache`), OpenTofu its providers (`okd-pve/tofu-plugins`). Needs ~2 GiB. Relative like `tmp_dir`, e.g. `.cache`. Default `$XDG_CACHE_HOME` or `~/.cache` |
| `host_memory_reserve_gib` | `8` | RAM per host kept free in the capacity check |
| `root_device_hint` | `serial` | install SCOS on the disk with the boot serial; `none` disables the hint |
| `upload_timeout` | `3600` | seconds for an ISO upload. The provider cancels every upload after 20 minutes anyway (default create timeout of the Terraform SDK), so values above `1200` have no effect. The ~1 GiB agent ISO therefore needs about 7 Mbit/s from your workstation to Proxmox; see the README, Troubleshooting |
| `ha.enabled` | `false` | Register every VM as Proxmox HA resource (state `started`): the HA manager restarts it on another node when its node fails. Needs shared VM storage, quorum after a node failure (two-node clusters need a QDevice) and `Sys.Audit` + `Sys.Console` on `/` (see [proxmox-permissions.md](proxmox-permissions.md)). |
| `ha.max_restart`, `ha.max_relocate` | `1`, `1` | Restart attempts on the same node and relocations to another node before HA gives up |
| `tags` | `false` | Proxmox tags `okd`, `okd-pve`, cluster name, roles. Needs `VM.Config.Options` on `/vms` (Proxmox ignores pool ACLs for tags at VM creation). |
| `guest_agent` | `true` | QEMU guest agent: Proxmox shows the IPs, shuts the VMs down through the agent and freezes the file systems for snapshot backups. SCOS ships and starts the agent. On existing VMs the change is applied with the next OpenTofu run (`create`, `node add`, `node remove`) but takes effect only after a power cycle in Proxmox (Shutdown + Start; a reboot inside the VM is not enough); drain the node first. Set `false` for images without the agent: Proxmox shutdown and reboot would time out. |

### network

| Key | Default | Description |
|---|---|---|
| `interface` | `ens18` | NIC name inside SCOS (net0 on Proxmox) |
| `prefix_length` | `24` | |
| `gateway` | – | default route |
| `dns_servers` | – | at least one |
| `ntp_servers` | – | at least three recommended |
| `rendezvous_ip` | – | IP of a control-plane node |

Static IPv4 only; the node network is configured with nmstate in
`agent-config.yaml`.

### hostname_format

| Key | Default | Description |
|---|---|---|
| `hostname_format` | `{cluster}-{group}-{index}` | hostname = Kubernetes node name = Proxmox VM name. Placeholders `{cluster}`, `{group}`, `{index}`, `{domain}` (baseDomain); must contain `{group}` and `{index}`. Example matching DNS records like `master-0.<cluster>.<domain>`: `{group}-{index}.{cluster}.{domain}` |

Keep the cluster name in the format: the Proxmox CSI driver finds VMs by
node name, so VM names must be unique across all clusters on the same
Proxmox. Changing the format of an existing cluster renames nothing; set it
before the first `create`.

### node_groups

A list; every entry is one group of identical VMs.

| Key | Description |
|---|---|
| `name` | DNS label; part of the hostname (`hostname_format`) |
| `roles` | list of `master`, `worker`, `infra`; `master` cannot be combined |
| `count` | number of nodes (masters: 1 or 3) |
| `cpu`, `memory_gib`, `disk_gib` | per VM; minimum 4/16/100 for masters, 2/8/100 otherwise |
| `ips` | addresses by index; ranges `a.b.c.d-a.b.c.e` allowed; list spares for `node add` |
| `data_disks` | extra raw disks: `[200]` or `[{size_gib: 200, storage: ceph-vm}]` |
| `taint_infra` | infra groups only; default `true` for `[infra]`, `false` for combined |
| `proxmox_nodes` | optional: restrict this group to these Proxmox nodes |
| `vmid_offset` | optional: explicit VMID offset instead of position × `vmid_block` |

Add new groups at the end of the list. Changes that would alter the VMID,
MAC or host of an existing VM are refused.

### registry_mirrors

Pull-through caches (Artifactory/Nexus remote repositories, Harbor proxy
projects). Details in [registry-mirrors.md](registry-mirrors.md).

| Key | Default | Description |
|---|---|---|
| `registries` | `[]` | `{source, mirror, fallback, username, password}` per source registry (only `source` and `mirror` required), e.g. `{source: quay.io, mirror: quay-cache.example.com}`; empty = no mirrors |
| `fallback` | `false` | default for entries without their own `fallback`. `false`: pull only from the mirror (`NeverContactSource`); `true`: fall back to the source. `create` sets the policy only after the installation; during it the nodes may fall back to the source (see [registry-mirrors.md](registry-mirrors.md)) |
| `username`, `password` | `""` | login for every mirror, merged into the pull secret; an entry in `registries` can set its own. `$OKD_PVE_MIRROR_PASSWORD` overrides `password`. The password is masked in all output |
| `auth_file` | `""` | auth.json (`podman login --authfile`) with credentials per mirror host, merged into the pull secret; `username`/`password` win for the same mirror |

## Environment variables

| Variable | Effect |
|---|---|
| `PROXMOX_VE_*` | override `proxmox.conf` |
| `OKD_PVE_PROXMOX_CONF` | other path for `proxmox.conf` |
| `OKD_PVE_HOOKS_DIR` | external hooks directory |
| `OKD_PVE_PULL_SECRET_FILE`, `OKD_PVE_SSH_PUBLIC_KEY_FILE` | see `install` |
| `OKD_PVE_MIRROR_PASSWORD` | password for `registry_mirrors.username`, overrides `registry_mirrors.password` |
| `PROXMOX_CSI_TOKEN`, `PROXMOX_CSI_ENDPOINT`, `PROXMOX_CSI_INSECURE` | Proxmox CSI credentials |
| `CEPH_USER_KEY` | Ceph CSI key |
| `OKD_PVE_TOFU_VERSION`, `OKD_PVE_BUTANE_VERSION`, `OKD_PVE_PROXMOX_PROVIDER_VERSION` | other pinned tool versions |
| `OKD_PVE_STATUS_INTERVAL` | seconds between status lines while waiting for bootstrap/installation, default `120`, `0` = off |
| `OKD_PVE_WAIT_RETRIES` | how often `create` waits again when openshift-install times out but the cluster still makes progress (more nodes Ready or operators available), default `3`, `0` = never |
| `TMPDIR`, `XDG_CACHE_HOME` | temporary and cache directory when `proxmox.tmp_dir` / `proxmox.cache_dir` are empty; those settings win |
| `NO_COLOR` | disable colors |
